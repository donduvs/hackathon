# Концепція інтеграції з іншими цифровими рішеннями у сфері доброчесності

## Ідея

Камертон відповідає на питання «на якому рівні зрілості перебуває система доброчесності і що робити далі». Інші цифрові рішення відповідають на суміжні питання: де ризики, які надходять повідомлення, хто пройшов навчання. Інтеграція потрібна для того, щоб думки респондентів зіставлялися з фактами, а рекомендації Камертона потрапляли туди, де їх виконують.

## Принципи

1. **Одноразове оцінювання — багаторазове використання.** Результати циклу доступні іншим системам через API, а не через повторний збір даних.
2. **Лише агрегати.** Між системами передаються числа за категоріями й закладом. Персональних даних Камертон не приймає й не передає.
3. **Пояснюваність.** Будь-який зовнішній показник, що впливає на сигнал чи рекомендацію, видно на сторінці питання разом з правилом.
4. **Людина ухвалює рішення.** Зовнішні дані породжують сигнали й пропозиції, а не автоматичні висновки.
5. **Відкриті формати.** JSON для обміну, DOCX і PDF для документів, налаштування у файлах JSON.

## Потоки даних

**До Камертона (об'єктивні показники):**
- охоплення антикорупційним навчанням — з системи управління навчанням;
- кількість повідомлень викривачів і строки їх розгляду — з даних уповноваженої особи щодо Єдиного порталу повідомлень викривачів;
- результати внутрішнього аудиту й перевірок — від підрозділу внутрішнього аудиту;
- стан виконання антикорупційних заходів — з плану заходів у системі документообігу.

Кожен показник прив'язується до питання анкети так само, як зараз прив'язано пункти чек-листа, і може породжувати сигнал розбіжності на кшталт R3.

**З Камертона:**
- Integrity Index, рівні компонентів і питань, сигнали — через `GET /api/cycles/{id}/summary`;
- прийняті рекомендації з відповідальними й строками — для систем документообігу й контролю доручень;
- звіт за формою Додатка Г — для звітування уповноваженої особи;
- узагальнені результати — для вебсайту закладу.

## Етапи

| Етап | Що зробити |
|---|---|
| Прототип (зараз) | API для читання результатів, звіти DOCX і PDF, налаштування у файлах |
| Пілот у закладі | вхід через обліковий запис закладу; імпорт об'єктивних показників із файла CSV; прив'язка показників до питань |
| Масштабування | API для запису показників (`POST`), вивантаження рекомендацій у систему документообігу, окремі набори анкет для інших органів сектору безпеки і оборони, зведені знеособлені дані для Департаменту з питань запобігання та виявлення корупції Міністерства оборони |

## Обмеження

Інтеграція з державними системами потребує погодження їхніх власників і захисту інформації в межах відомчого контуру. Прототип не підключається до жодної реальної системи й працює лише з синтетичними даними.
